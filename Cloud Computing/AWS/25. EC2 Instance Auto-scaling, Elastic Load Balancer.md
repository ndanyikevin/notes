
Auto-scaling = Scale out and Scale in EC2 instances based on demand.
Whenever there's demand on the traffic ASG will Scale Out and Scale in EC2 instances automatically.

ELB does health checks to the application.
Cloudwatch will monitor the EC2 instances.

Min - The minimum number of EC2 instances that ASG should have e.g Min=2
Max - The Max number of EC2 instances that ASG should have e.g Max=6
Desired Capacity - The number of EC2 instances that you wish to launch initially

### Types of Scaling Options
---
1. Manual scaling - If you are manually modifying min, max , dc
2. Schedule scaling - Based on the time period or a day
3. Dynamic scaling - Based on the load/traffic (CPU metrics, network, request count etc) using cloudwatch (metrics)

### Lauch template (previously called Lauch Configuration)
---
Custom AMI(app) or AWS AMI, volumes, SG, instance type, key-pair, tag etc
ASG = ELB + EC2 instances + Launch templates + SNS
ASG has lauch template attached.


## Elastic Load Balancer
---
Distributes traffic to multiple EC2 instances across Availability Zones.
It's completely managed by AWS
ELB is a Service for us not server
ELB can be accessed using DNS Name or URL
You cannot login to the ELB
ELB has dynamic IP addresses
AWS always recommend to use the ELB DNS name not the IP addresses


#### Types of Load Balancers
---
* Classic load balancers . Previous generation . 
* Application Load Balancer. ALB.Works on Layer 7. Best for Microservices. Works on HTTP and HTTPS.
* Network Load Balancer. NLB. Works on layer 4. Works on TCP and UDP. Works when you need Extreme high perfomance. It has 1 static IP per AZ
* Gateway Load Balancer. GLB. Works on Layer 3(Network layer). It is used to deploy, manage and scale a fleet of 3rd party network virtual appliances in AWS firewall, prevention systems etc. Works on GENEVE protocal 6081
---

#### Application Load Balancer
---
It has three routing features.
* Host based routing
* Path based routing
* String parameter routing
