In **Kubernetes**, a **configuration** is **external data that controls how your application behaves**, without changing the application code or rebuilding the image.

> **Config = settings, not code**

---

## Why configuration exists

You don’t want to:

- hard-code database URLs
    
- rebuild images for every environment
    
- commit secrets to Git
    

So Kubernetes lets you **inject configuration at runtime**.

---

## Main Kubernetes configuration types

### 1. ConfigMap (non-secret config)

Used for:

- environment variables
    
- app settings
    
- config files
    

Example:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  NODE_ENV: production
  API_URL: https://api.example.com
```

Use it in a Pod:

```yaml
envFrom:
  - configMapRef:
      name: app-config
```

---

### 2. Secret (sensitive config 🔒)

Used for:

- passwords
    
- API keys
    
- tokens
    

Example:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-secret
type: Opaque
data:
  DB_PASSWORD: cGFzc3dvcmQ=   # base64
```

---

### 3. Environment variables

ConfigMaps and Secrets are usually injected as:

- env vars
    
- mounted files
    

---

### 4. Volume-based config

Used when apps expect config files:

```yaml
volumeMounts:
  - name: config
    mountPath: /etc/app
```

---

## ConfigMap vs Secret

|Feature|ConfigMap|Secret|
|---|---|---|
|Sensitive data|❌|✅|
|Base64 encoded|❌|✅|
|Git-friendly|✅|⚠️|
|Examples|URLs, flags|passwords, tokens|

---

## Real-world example

For your **Hono API**:

- `DATABASE_URL` → Secret
    
- `NODE_ENV` → ConfigMap
    

Change config → **restart Pods**, not rebuild images.

---

## Why this matters

- Same Docker image for dev, staging, prod
    
- Safer secrets handling
    
- Cleaner deployments
    

---

## Mental model

- **Code** → inside container image
    
- **Configuration** → injected at runtime
    
- **Secrets** → locked configuration
    

---

## One-sentence summary

> **Configuration in Kubernetes is external data (ConfigMaps & Secrets) that control app behavior without changing code.**
