In **Kubernetes**, an **Ingress** is an object that **manages external HTTP/HTTPS access to Services** inside your cluster.

> **Ingress = smart HTTP router for your cluster**

---

## Why Ingress exists

Without Ingress:

- You expose every app with a **LoadBalancer or NodePort**
    
- You pay for many load balancers
    
- No central place for routing, TLS, or domains
    

Ingress solves this by:

- Using **one entry point**
    
- Routing traffic to **multiple Services**
    
- Handling **domains, paths, and HTTPS**
    

---

## Simple flow

```
Internet
   ↓
Ingress Controller (Nginx / Traefik)
   ↓
Service
   ↓
Pods
```

⚠️ **Ingress itself does nothing without an Ingress Controller**

---

## What an Ingress can do

### 1. Host-based routing

```text
api.example.com   → api-service
app.example.com   → frontend-service
```

---

### 2. Path-based routing

```text
example.com/api   → api-service
example.com       → frontend-service
```

---

### 3. TLS / HTTPS

- Terminates SSL
    
- Manages certificates (often via cert-manager + Let’s Encrypt)
    

---

## Basic Ingress example

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
spec:
  rules:
    - host: example.com
      http:
        paths:
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: api-service
                port:
                  number: 80
```

Now:

```
https://example.com/api → api-service → Pods
```

## Ingress vs Service (very important)

|Feature|Service|Ingress|
|---|---|---|
|Exposes Pods|✅|❌|
|HTTP routing|❌|✅|
|Path/host rules|❌|✅|
|TLS/HTTPS|❌|✅|
|Load balancing|✅|✅ (HTTP level)|

➡️ **Ingress routes to Services, not Pods**

## Ingress Controller (required)

Common controllers:

- **Nginx Ingress**
    
- **Traefik**
    
- **HAProxy**
    
- **Cloud Ingress (GKE, EKS, AKS)**


## When to use Ingress

✅ Use when:

- You have multiple web apps
    
- You need HTTPS
    
- You use real domains
    
- Production setups
    

❌ Not needed for:

- internal-only services
    
- TCP/UDP-only traffic
    

---

## One-line summary

> **Ingress exposes HTTP/HTTPS routes from outside the cluster to Services inside the cluster.**
