In **Kubernetes**, a **Service** is an object that gives your app a **stable way to be reached** over the network.

> **Pods are temporary. Services are stable.**

---

## The problem Services solve

Pods:

- get **random IP addresses**
    
- can be **destroyed and recreated**
    
- scale up and down
    

So if your frontend tries to talk to a Pod directly… it will break 😬

➡️ **Service sits in front of Pods** and provides:

- a **fixed IP / DNS name**
    
- **load balancing** across Pods
    

---

## Simple definition

**A Service is a stable network endpoint that exposes a set of Pods.**

---

## How it works (simple flow)

```
Client → Service → Pod A
               → Pod B
               → Pod C
```

The Service:

- finds Pods using **labels**
    
- distributes traffic among them
    

---

## Types of Kubernetes Services

### 1. ClusterIP (default)

📦 **Internal-only service**

- Only accessible **inside the cluster**
    
- Used for backend APIs, databases
    

```yaml
type: ClusterIP
```

Example:

- Frontend → Backend API
    
- API → Database
    

---

### 2. NodePort

🌐 **Exposes app on each node’s IP**

- Accessible from outside
    
- Uses a port like `30000–32767`
    

```yaml
type: NodePort
```

Access:

```
http://<node-ip>:30080
```

Good for:

- testing
    
- small setups
    

---

### 3. LoadBalancer

☁️ **Cloud-friendly external access**

- Creates a cloud load balancer (AWS, GCP, Azure)
    
- Best for production external access
    

```yaml
type: LoadBalancer
```

---

### 4. Headless Service

🧠 **No load balancing**

- `clusterIP: None`
    
- Used for Stateful apps (e.g. databases)
    

```yaml
clusterIP: None
```

---

## Example (very common)

### Deployment (Pods)

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
        - name: api
          image: my-api
          ports:
            - containerPort: 3000
```

### Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: api-service
spec:
  selector:
    app: api
  ports:
    - port: 80
      targetPort: 3000
```

Now:

- Pods can die / restart
    
- **api-service** stays reachable at:
    

```
http://api-service
```

---

## Service vs Ingress (important)

- **Service** → exposes Pods
    
- **Ingress** → routes HTTP traffic _to Services_
    

```
Internet → Ingress → Service → Pods
```
