In **Kubernetes**, a **cluster** is a **group of machines that work together to run your applications**.

> **Cluster = the whole Kubernetes system**

---

## Simple definition

**A Kubernetes cluster is a set of computers (nodes) managed by Kubernetes to run containerized apps.**

You **deploy to the cluster**, not to individual machines.

---

## What makes up a cluster?

### 1. Control Plane (the “brain” 🧠)

Decides **what should run and where**.

Main parts (conceptually):

- **API Server** – entry point (`kubectl`)
    
- **Scheduler** – picks which node runs a Pod
    
- **Controller Manager** – keeps desired state
    
- **etcd** – stores cluster state (database)
    

👉 You usually **don’t manage this yourself** on cloud or managed K8s.

---

### 2. Nodes (the “workers” 💪)

Machines that **actually run your containers**.

Each node has:

- container runtime (Docker / containerd / Podman)
    
- **kubelet** (talks to control plane)
    
- kube-proxy (networking)
    

Nodes can be:

- virtual machines
    
- physical servers

## Why clusters are powerful

### High availability

If one node dies 💥:

- Pods are moved to other nodes
    

---

### Scaling

- Add more nodes → cluster gets bigger
    
- Kubernetes automatically uses them
    

---

### Resource sharing

Multiple apps can safely run in the **same cluster**.

---

## Types of clusters

### Local clusters (learning/dev)

- Minikube
    
- Kind
    
- k3s
    

Runs on your laptop.

---

### Cloud / Managed clusters (production)

- AWS EKS
    
- GCP GKE
    
- Azure AKS
    
- DigitalOcean Kubernetes
    

Provider manages the control plane.

---

### On-prem clusters

- You manage everything yourself
    
- Used in enterprises / data centers
    

---

## Cluster vs Node (common confusion)

|Term|Meaning|
|---|---|
|Cluster|Whole system|
|Node|One machine in the cluster|
|Pod|Runs on a node|
|Service|Exposes Pods|
|Ingress|External HTTP access|
