In **Kubernetes**, a **Deployment** is an object that **describes how your application should run** and lets Kubernetes **manage Pods for you automatically**.

> **Deployment = “this is how my app should run”**

---

## Why Deployments exist

Pods are:

- temporary
    
- easy to break
    
- not self-managed
    

If you create Pods directly:

- no auto-restart
    
- no scaling
    
- no safe updates
    

➡️ **Deployment fixes all of this**.

---

## Simple definition

**A Deployment tells Kubernetes:**

- which container image to run
    
- how many copies (replicas)
    
- how to update them safely
    
- how to recover from failures
    

Kubernetes then **creates and manages Pods for you**.

---

## What a Deployment does

### 1. Creates Pods

You say:

```yaml
replicas: 3
```

Kubernetes runs **3 identical Pods**.

---

### 2. Self-healing

If a Pod crashes or a node dies:

- Kubernetes automatically creates a new Pod
    

---

### 3. Scaling

```bash
kubectl scale deployment api --replicas=5
```

---

### 4. Rolling updates (zero downtime)

When you deploy a new version:

- old Pods are replaced **gradually**
    
- users never notice downtime
    

---

### 5. Rollbacks

If something breaks:

```bash
kubectl rollout undo deployment api
```

---

## How Deployment fits in the big picture

```
Deployment
   ↓
ReplicaSet
   ↓
Pods
```

You usually **never touch ReplicaSets directly**.

---

## Basic Deployment example

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
        - name: api
          image: my-api:1.0
          ports:
            - containerPort: 3000
```

---

## Deployment vs Pod (important)

|Pod|Deployment|
|---|---|
|Single instance|Manages many Pods|
|No auto-restart|Self-healing|
|Manual scaling|Automatic scaling|
|No updates|Rolling updates|

👉 **In real apps, you almost always use Deployments.**

---

## Deployment vs StatefulSet

- **Deployment** → stateless apps (APIs, frontends)
    
- **StatefulSet** → stateful apps (databases)
    

---

## Real-world example

For your **SolidJS frontend + Hono API**:

- frontend → Deployment
    
- API → Deployment
    
- PostgreSQL → StatefulSet
    

---

## Mental model

- **Pod** = one running instance
    
- **Deployment** = manager that keeps Pods running correctly
