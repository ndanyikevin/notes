At its core, **Kubernetes** (often abbreviated as **K8s**) is an open-source platform designed to automate the deployment, scaling, and management of containerized applications.1

If you think of a **Docker container** as a single shipping container, Kubernetes is the **crane and the cargo ship** that decides where those containers go, how they are stacked, and what to do if one starts leaking.

---

## 1. How Kubernetes Works (The Architecture)

Kubernetes works on a cluster system.2 A cluster consists of at least one **Control Plane** (the brains) and multiple **Nodes** (the workers).3

### Key Components:

- **Pods:** The smallest deployable units in K8s.4 A Pod represents a single instance of a running process in your cluster and can contain one or more containers.5
    
- **Nodes:** These are the machines (physical or virtual) that run your applications.6
    
- **Control Plane:** The orchestration layer that exposes the API, schedules workloads, and manages the state of the cluster.
    
- **Services:** An abstract way to expose an application running on a set of Pods as a network service, ensuring traffic reaches the right place even as Pods are created or destroyed.7
    

---

## 2. Why do we need it?

In modern software, applications are broken down into small pieces called **microservices**.8 Managing hundreds or thousands of these manually is impossible. Kubernetes provides:

- **Self-healing:** If a container crashes, Kubernetes automatically restarts it. If a node dies, it moves the containers to a healthy node.
    
- **Auto-scaling:** It can automatically grow or shrink the number of running containers based on CPU or memory usage.9
    
- **Load Balancing:** It distributes network traffic so that no single container is overwhelmed.10
    
- **Rollouts and Rollbacks:** You can deploy new versions of your app without downtime.11 If something goes wrong, you can instantly roll back to the previous version.

## 3. Example: A Simple Deployment

To give you a practical look at how you interact with Kubernetes, we use **YAML** files to describe the "desired state" of the cluster.12 Following your preference, here is a complete, standard Deployment component for a web application.

YAML

```
# kubernetes-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app-deployment
  labels:
    app: my-website
spec:
  replicas: 3 # Tells K8s to always keep 3 copies of this app running
  selector:
    matchLabels:
      app: my-website
  template:
    metadata:
      labels:
        app: my-website
    spec:
      containers:
      - name: nginx-container
        image: nginx:1.21.0 # The container image to run
        ports:
        - containerPort: 80
        resources:
          limits:
            memory: "256Mi"
            cpu: "500m"
          requests:
            memory: "128Mi"
            cpu: "250m"
---
# Service component to expose the deployment
apiVersion: v1
kind: Service
metadata:
  name: web-app-service
spec:
  selector:
    app: my-website
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: LoadBalancer
```
