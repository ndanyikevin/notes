
### 🧭 What the ConfigModule Is

The `@nestjs/config` module provides a **centralized, safe way to manage environment variables and app configuration** in NestJS.

Think of it as your **.env manager** — it loads `.env` files, validates them, and makes their values available everywhere in your app (controllers, services, etc.).

---

### 🧩 Installation

```bash
npm install @nestjs/config
```

---

### ⚙️ Basic Setup

In your `app.module.ts` (or `root` module):

```ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import { TypeOrmModule } from '@nestjs/typeorm';
import { Property } from './entities/property.entity';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true, // makes it available everywhere
      envFilePath: '.env', // default
    }),

    TypeOrmModule.forRoot({
      type: 'postgres',
      host: process.env.DB_HOST,
      port: parseInt(process.env.DB_PORT ?? '5432', 10),
      username: process.env.DB_USER,
      password: process.env.DB_PASS,
      database: process.env.DB_NAME,
      entities: [Property],
      synchronize: true, // only in dev
    }),
  ],
})
export class AppModule {}
```

---

### 📦 Example `.env` File

```env
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASS=1234
DB_NAME=my_app_db
```

### 🔍 Using ConfigService in Your Code

Once it’s global, you can inject it anywhere:

```ts
import { ConfigService } from '@nestjs/config';
import { Injectable } from '@nestjs/common';

@Injectable()
export class SomeService {
  constructor(private configService: ConfigService) {}

  getDbUser() {
    return this.configService.get<string>('DB_USER');
  }
}
```

### ✅ Why It’s Useful

- Keeps credentials and secrets out of code
    
- Handles multiple environments (dev, prod, test) easily
    
- Plays nicely with Docker, CI/CD, etc.
    
- Lets you **validate env values** (using `@hapi/joi`)
