
## 🧩 What Is Rate Limiting?

**Rate limiting** means **restricting how many requests** a client (like a browser or API consumer) can make to your server **within a specific time period**.

It helps protect your app from:

- 🧨 **DDoS attacks** (too many requests at once)
    
- 🕵️‍♂️ **Brute-force login attempts**
    
- 💸 **Excessive usage** (abusing free APIs)
    

---

### 💡 Example

Let’s say you limit users to:

> **100 requests per minute per IP**

If someone sends the 101st request in that same minute, the server responds with:

```json
{
  "statusCode": 429,
  "message": "Too Many Requests"
}
```

---

## ⚙️ How Rate Limiting Works in NestJS

NestJS doesn’t do rate limiting by default —  
but it provides an **official package** built on top of `express-rate-limit` or `fastify-rate-limit`.

### ✅ Install the Throttler Module

```bash
npm install @nestjs/throttler
```

---

## 🧩 Set Up Global Rate Limiting

In your `app.module.ts`:

```ts
import { Module } from '@nestjs/common';
import { ThrottlerModule } from '@nestjs/throttler';

@Module({
  imports: [
    ThrottlerModule.forRoot({
      ttl: 60,       // ⏱ Time window in seconds (1 minute)
      limit: 10,     // 🔢 Max 10 requests per IP per minute
    }),
  ],
})
export class AppModule {}
```

✅ This automatically applies rate limiting to **all routes** in your app.

---

## 🚀 Customize Per Route (Optional)

If you want **different limits** for certain routes, you can use the `@Throttle()` decorator.

Example:

```ts
import { Controller, Get } from '@nestjs/common';
import { Throttle } from '@nestjs/throttler';

@Controller('auth')
export class AuthController {
  // 👇 Max 5 requests per 60 seconds
  @Throttle(5, 60)
  @Get('login')
  login() {
    return 'Login route';
  }

  // 👇 Uses the global limit (10/min)
  @Get('register')
  register() {
    return 'Register route';
  }
}
```

---

## 🧠 Explanation of Options

|Option|Meaning|
|---|---|
|`ttl`|“Time To Live” — time window in seconds (e.g., 60 = 1 minute)|
|`limit`|Number of requests allowed within that time per client|
|`@Throttle(limit, ttl)`|Custom limit for a specific route or controller|

---

## ⚙️ Example Response When Limit Is Exceeded

When a client exceeds the limit, NestJS automatically returns:

```json
{
  "statusCode": 429,
  "message": "Too Many Requests"
}
```

and includes helpful HTTP headers like:

```
Retry-After: 60
```

---

## 🧰 Optional — Apply Globally in `main.ts`

You can also manually apply the rate limiting guard:

```ts
import { ThrottlerGuard } from '@nestjs/throttler';
import { APP_GUARD } from '@nestjs/core';

@Module({
  imports: [
    ThrottlerModule.forRoot({ ttl: 60, limit: 10 }),
  ],
  providers: [
    {
      provide: APP_GUARD,
      useClass: ThrottlerGuard, // 👈 applies globally
    },
  ],
})
export class AppModule {}
```

## 🧠 Why Rate Limiting Matters

|Benefit|Description|
|---|---|
|🔒 Security|Prevents brute-force attacks|
|💰 Cost Control|Avoids overuse of resources|
|⚖️ Fair Usage|Ensures equal access for all users|
|🚀 Stability|Keeps your API responsive under heavy load|

## ✅ Summary

|Concept|Meaning|
|---|---|
|**Rate limiting**|Restrict requests per time period|
|**Default status**|Not enabled automatically|
|**Enable with**|`@nestjs/throttler`|
|**Global config**|`ThrottlerModule.forRoot()`|
|**Per route config**|`@Throttle()`|
|**Error code**|`429 Too Many Requests`|
