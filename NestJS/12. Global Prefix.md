
## 🧩 What Is a Global Prefix?

A **global prefix** is a **base path** that NestJS automatically adds in front of **all routes** in your application.

It’s often used to:

- Group all API routes under a common path (like `/api` or `/v1`)
    
- Separate API routes from other parts of your app (like a frontend)
    
- Version your API easily
    

---

### ⚙️ Without a Global Prefix

Let’s say you have this controller:

```ts
@Controller('users')
export class UsersController {
  @Get()
  findAll() {
    return ['Alice', 'Bob'];
  }
}
```

When you run your app, the endpoint will be:

```
GET /users
```

---

### 🚀 With a Global Prefix

In your `main.ts` file, set a prefix before starting the app:

```ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.setGlobalPrefix('api'); // 👈 sets a global prefix

  await app.listen(3000);
}
bootstrap();
```

Now, **all routes automatically include `/api/`** at the start.

```
GET /api/users
```

✅ This helps organize routes and prevent conflicts with other paths (like a frontend app).

---

### 🧠 Why It’s Useful

|Purpose|Example|
|---|---|
|**API versioning**|`/api/v1/users`, `/api/v2/users`|
|**Frontend separation**|Your React app serves `/`, while NestJS serves `/api/*`|
|**Reverse proxies or Nginx routing**|Makes routing rules simpler and safer|

---

### 💡 Advanced Example — API Versioning

You can even include versioning inside the prefix:

```ts
app.setGlobalPrefix('api/v1');
```

Then your routes look like:

```
GET /api/v1/users
POST /api/v1/auth/login
```

---

### ⚙️ Optional Configuration

If you want **some routes excluded** from the prefix (e.g., `/health` or `/docs`), you can pass options:

```ts
app.setGlobalPrefix('api', {
  exclude: ['health', 'docs'],
});
```

So:

- `/api/users` → ✅ prefixed
    
- `/health` → ❌ not prefixed
    

---

### ✅ Summary

|Concept|Description|
|---|---|
|**Global prefix**|A base path prepended to every route|
|**Set in**|`main.ts` via `app.setGlobalPrefix()`|
|**Common examples**|`'api'`, `'api/v1'`, `'backend'`|
|**Use cases**|API versioning, frontend separation, clean routing|
