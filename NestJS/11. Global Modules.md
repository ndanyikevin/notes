
## 🧩 What Is a Global Module?

A **global module** in NestJS is a module whose **providers (services, etc.) are available everywhere** in your application — **without needing to import the module** in every other module.

---

### ⚙️ Normally in NestJS

If you have a `PrismaModule` like this:

```ts
@Module({
  providers: [PrismaService],
  exports: [PrismaService],
})
export class PrismaModule {}
```

You’d have to import it everywhere you need it:

```ts
@Module({
  imports: [PrismaModule],
  providers: [UsersService],
})
export class UsersModule {}
```

✅ Works fine — but becomes repetitive if many modules need the same service.

---

### 🚀 Global Module to the Rescue

You can make a module **global** using the `@Global()` decorator.

```ts
import { Module, Global } from '@nestjs/common';
import { PrismaService } from './prisma.service';

@Global() // 👈 makes it available everywhere
@Module({
  providers: [PrismaService],
  exports: [PrismaService],
})
export class PrismaModule {}
```

Now:

- You register `PrismaModule` **once** in the `AppModule`
    
- All other modules automatically have access to `PrismaService`
    

---

### ✅ Example in `app.module.ts`

```ts
import { Module } from '@nestjs/common';
import { PrismaModule } from './prisma/prisma.module';
import { UsersModule } from './users/users.module';

@Module({
  imports: [PrismaModule, UsersModule], // PrismaModule registered once
})
export class AppModule {}
```

After this:

> You **do not need** to import `PrismaModule` again in any other module like `UsersModule`, `AuthModule`, etc.

They can directly inject `PrismaService` anywhere.

---

### ⚠️ When to Use Global Modules

✅ Use global modules for:

- **Common services** used across many parts of the app  
    e.g., `PrismaService`, `ConfigService`, `LoggerService`, `CacheService`, etc.
    

❌ Avoid making everything global — it can:

- Hide dependencies (less explicit)
    
- Make modules harder to test and maintain
    

---

### 💡 Tip: Good Practice

If a service is used by most of your app (e.g. database connection, environment variables), make its module **global**.  
If a service is feature-specific (e.g. `UsersService`, `OrdersService`), **keep it local**.
