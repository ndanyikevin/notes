
Controllers in **NestJS** are responsible for **handling incoming requests** and **returning responses** to the client.

They act as the first contact point between the client and your backend API.

---

### ✅ What Controllers Do

|Responsibility|Description|
|---|---|
|Define **routes**|e.g., GET /users|
|Receive requests|Path params, query params, body|
|Return responses|JSON, status codes|
|Delegate logic|Call services to do actual work|

---

### 📌 Key Point

> Controllers **should not contain business logic** — they simply handle HTTP communication and forward tasks to services.

---

### ✅ Example Controller

```ts
import { Controller, Get, Post, Body } from '@nestjs/common';
import { UsersService } from './users.service';

@Controller('users') // Base route: /users
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Get() // GET /users
  findAll() {
    return this.usersService.findAll();
  }

  @Post() // POST /users
  create(@Body() userDto: any) {
    return this.usersService.create(userDto);
  }
}
```

---

### ▶️ What’s Happening Here?

- `@Controller('users')` → This controller handles `/users` routes
    
- `@Get()` → Handles GET requests
    
- `@Post()` → Handles POST requests
    
- Uses `UsersService` to process data
    

---

### ✅ Controller Doesn’t Do This

🚫 Query database  
🚫 Validate deeply  
🚫 Perform calculations  
🚫 Contain business rules

👉 All handled by **Services**

---

### 🧠 Best Practice

|Controllers|Services|
|---|---|
|Handle HTTP stuff|Handle business logic|
|Routing|Database calls|
|Transform req → DTO|Validation & processing|
|Return response|Interact with repositories|

---

### Quick Visual

```
Client → Controller → Service → Database (or other logic)
```

---

### Summary ✅

- Controllers = HTTP request/response managers
    
- Very thin, no heavy logic
    
- Use decorators like `@Get()`, `@Post()`, `@Put()`, etc.
    
- Always call services to handle real work
