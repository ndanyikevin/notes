
## 🧩 What Is Dependency Injection (DI)?

**Dependency Injection (DI)** is a **design pattern** where a class **does not create its own dependencies** — instead, those dependencies are **provided (injected)** to it from the outside.

---

### 🔍 Example Without Dependency Injection

Let’s say you have a `UsersService` that needs a `DatabaseService`.

```ts
class DatabaseService {
  connect() {
    console.log('Connected to database');
  }
}

class UsersService {
  private db: DatabaseService;

  constructor() {
    // ❌ Creating dependency manually
    this.db = new DatabaseService();
  }

  getUsers() {
    this.db.connect();
    return ['Alice', 'Bob'];
  }
}
```

**Problem:**

- `UsersService` is tightly coupled to `DatabaseService`.
    
- You can’t easily replace `DatabaseService` (e.g., for testing or switching databases).
    

---

### ✅ Example With Dependency Injection

Let’s now let **NestJS inject** the dependency.

```ts
import { Injectable } from '@nestjs/common';

@Injectable()
class DatabaseService {
  connect() {
    console.log('Connected to database');
  }
}

@Injectable()
class UsersService {
  constructor(private db: DatabaseService) {} // 👈 injected automatically

  getUsers() {
    this.db.connect();
    return ['Alice', 'Bob'];
  }
}
```

Then in your module:

```ts
import { Module } from '@nestjs/common';

@Module({
  providers: [DatabaseService, UsersService],
})
export class AppModule {}
```

✅ Now NestJS automatically:

1. Creates a single instance of `DatabaseService`
    
2. Injects it into `UsersService`
    
3. Manages its lifecycle
    

---

### 🧠 In Simple Words

|Concept|Meaning|
|---|---|
|**Dependency**|Something a class needs to work (like a service or helper).|
|**Injection**|Giving that dependency to the class instead of making it inside.|
|**NestJS Role**|Nest’s IoC (Inversion of Control) container automatically manages this process.|

---

### 💡 Why It’s Powerful

- 🔁 **Reusability:** You can easily swap dependencies (e.g., fake DB for tests)
    
- 🧱 **Modularity:** Each part of your app focuses on its job
    
- 🧪 **Testability:** You can mock or stub services during unit tests
    
- 🧠 **Maintainability:** Fewer hard-coded connections between classes
    

---

### ⚙️ Real NestJS Example

```ts
@Injectable()
export class PrismaService {
  // handles DB connection
}

@Injectable()
export class UsersService {
  constructor(private prisma: PrismaService) {} // 👈 Nest injects it

  findAll() {
    return this.prisma.user.findMany();
  }
}
```

Here:

- `UsersService` depends on `PrismaService`
    
- `AppModule` registers both
    
- NestJS automatically injects `PrismaService` when `UsersService` is created
