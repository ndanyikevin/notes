This is the point where we move from "database design" to "building the engine." Since this system is going to be massive, you cannot afford to write the same `try/catch` blocks or `c.json` responses in every single file.

To make this a truly "never seen before" system, we will implement a **Unified Service/Controller Pattern** and a **Global Error Handler**.

### 1. The Global Result Wrapper

In a multi-tenant app, consistency is key. We want every API response to look exactly the same.

**`src/utils/response.ts`**

TypeScript

```
import { Context } from "hono";

export const sendResponse = (c: Context, data: any, message = "Success", status = 200) => {
  return c.json({
    success: true,
    message,
    data,
    schoolId: c.get("schoolId"), // Echo back the tenant context for safety
  }, status as any);
};

export class AppError extends Error {
  constructor(public message: string, public statusCode: number = 400) {
    super(message);
  }
}
```

### 2. The Global Error Middleware

This middleware catches any `AppError` thrown anywhere in your logic and formats it into a JSON response. No more server crashes!

**`src/middleware/error.middleware.ts`**

TypeScript

```
import { Context } from "hono";
import { AppError } from "../utils/response.js";

export const errorHandler = (err: Error, c: Context) => {
  if (err instanceof AppError) {
    return c.json({ success: false, error: err.message }, err.statusCode as any);
  }

  console.error(`[CRITICAL ERROR]: ${err.stack}`);
  return c.json({ success: false, error: "Internal Server Error" }, 500);
};
```

### 3. The Base Service (The "Secret Sauce")

Instead of writing CRUD logic for `Students`, `Teachers`, and `Items` separately, we create a Base Service that handles the common logic.

**`src/modules/base.service.ts`**

TypeScript

```
import { db } from "../db/index.js";
import { eq, and } from "drizzle-orm";
import { AppError } from "../utils/response.js";

export class BaseService {
  constructor(protected table: any) {}

  // Automatically filters by schoolId for multi-tenancy
  async findAll(schoolId: string) {
    return await db.select().from(this.table).where(eq(this.table.schoolId, schoolId));
  }

  async findById(id: string | number, schoolId: string) {
    const [result] = await db.select().from(this.table).where(
      and(eq(this.table.id, id), eq(this.table.schoolId, schoolId))
    );
    if (!result) throw new AppError("Resource not found", 404);
    return result;
  }

  async create(data: any) {
    return await db.insert(this.table).values(data).returning();
  }
}
```

### 4. Implementation: The Finance Service

Now, look how clean your specific services become. You only write the "unique" logic.

**`src/modules/finance/payment.service.ts`**

TypeScript

```
import { payments, studentBalances } from "../../db/schema/finance/transactions.js";
import { BaseService } from "../base.service.js";
import { db } from "../../db/index.js";
import { eq, sql } from "drizzle-orm";

export class PaymentService extends BaseService {
  constructor() {
    super(payments);
  }

  // Custom logic unique to payments
  async processPayment(data: typeof payments.$inferInsert) {
    return await db.transaction(async (tx) => {
      // 1. Record the payment
      const [newPayment] = await tx.insert(payments).values(data).returning();

      // 2. Update the student balance (Atomic update)
      await tx.update(studentBalances)
        .set({ 
          balance: sql`${studentBalances.balance} - ${data.amount}`,
          updatedAt: new Date()
        })
        .where(eq(studentBalances.studentId, data.studentId));

      return newPayment;
    });
  }
}
```

### 5. Final App Setup (`src/index.ts`)

This is how you bring it all together in Hono.

TypeScript

```
import { Hono } from "hono";
import { errorHandler } from "./middleware/error.middleware.js";
import { tenantMiddleware } from "./middleware/tenant.middleware.js";
import paymentRoutes from "./modules/finance/payment.routes.js";

const app = new Hono();

// Global Middleware
app.use("*", tenantMiddleware);
app.onError(errorHandler);

// Routes
app.route("/api/finance/payments", paymentRoutes);

export default app;
```

### Why this is "Never Seen Before":

1. **Safety:** The `BaseService` makes it almost impossible to forget the `schoolId` filter.
    
2. **Transactionality:** Complex Kenyan operations (like paying fees and updating balances simultaneously) are handled in atomic blocks.
    
3. **Speed:** You can spin up a new module (like "Transport" or "Boarding") in minutes because 80% of the logic is already in the `BaseService`.
