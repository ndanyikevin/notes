**Caching** is a technique where you **store a copy of data or a response** so that the **next time it’s requested, it can be returned faster** without recomputing or refetching it.

---

## Simple definition

> **Caching = remember the result so you don’t redo the work**

---

## Basic idea

Without cache:

```
Client → Server → Database → Server → Client
```

With cache:

```
Client → Cache → Client
```

If the data is **already cached**, the database is not touched.

---

## Why caching matters

### 🚀 Performance

- Faster responses
    
- Lower latency
    

### 💸 Cost reduction

- Fewer DB queries
    
- Less CPU usage
    

### 📈 Scalability

- Handle more users with the same infrastructure
    

---

## Where caching happens (very important)

### 1️⃣ Browser cache (client-side)

- CSS, JS, images
    
- Controlled by HTTP headers
    

```
Cache-Control: max-age=86400
```

---

### 2️⃣ Reverse proxy cache (NGINX, CDN)

- Caches API responses or pages
    
- Shared by many users
    

```
Client → NGINX Cache → Backend
```

---

### 3️⃣ Application cache

- In-memory cache inside your app
    
- Example: Node/Bun memory, LRU cache
    

---

### 4️⃣ Distributed cache

- Shared cache for many servers
    

Examples:

- Redis
    
- Memcached
    

```
API → Redis → Database
```

---

## Simple real-life analogy

Imagine a teacher answering the same question repeatedly.

- Without cache → explains every time
    
- With cache → writes answer on the board
    

That board = **cache**

---

## Types of caching

### 🔹 Data cache

Stores:

- DB query results
    
- Objects
    
- JSON responses
    

Example:

```json
{ "users": [...] }
```

---

### 🔹 HTTP response cache

Stores:

- Full HTTP response
    
- Headers + body
    

Used by:

- browsers
    
- CDNs
    
- reverse proxies
    

---

### 🔹 Static asset cache

Stores:

- images
    
- JS
    
- CSS
    

Best for:

- websites
    
- SPAs
    

---

## Cache expiration (TTL)

Cache must **expire** to avoid stale data.

Example:

```
TTL = 60 seconds
```

After 60 seconds → cache is refreshed.

---

## Cache invalidation (the hard part 😄)

When data changes:

- update cache
    
- or delete cache
    

Strategies:

- **Time-based** (TTL)
    
- **Write-through**
    
- **Cache busting**
    

---

## Caching with NGINX (example)

```nginx
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=my_cache:10m;

server {
    location /api/ {
        proxy_cache my_cache;
        proxy_cache_valid 200 60s;
        proxy_pass http://backend;
    }
}
```

---

## Caching with Redis (conceptual)

```ts
const cached = await redis.get("users");

if (cached) return JSON.parse(cached);

const users = await db.users.findMany();
await redis.set("users", JSON.stringify(users), "EX", 60);

return users;
```

## When should YOU use caching?

Given you’re working with:

- APIs (Hono, Bun)
    
- Docker
    
- NGINX
    
- Postgres
    

You should cache:

- **Read-heavy API endpoints**
    
- **Reference data**
    
- **Public GET requests**
    

Avoid caching:

- auth responses
    
- user-specific sensitive data
    
- frequently changing data
