In a standard Linux environment (like Ubuntu or CentOS), NGINX follows a predictable structure.1 The configuration is centralized in `/etc/nginx`, while the content it serves and its logs are stored in other standard system directories.

### 1. The Configuration Directory: `/etc/nginx/`

This is the heart of NGINX. Almost everything you do to customize the server happens here.

- **`nginx.conf`**: The main configuration file.2 it loads all other configurations and defines global settings like user permissions and worker processes.3
    
- **`conf.d/`**: A directory used for global configuration snippets.4 Any file ending in `.conf` here is usually automatically included in the main `nginx.conf`.
    
- **`sites-available/`**: Contains configuration files for individual websites (Virtual Hosts).5 Files here are **not active** until they are linked to the next folder.
    
- **`sites-enabled/`**: Contains symbolic links to the files in `sites-available`. 6NGINX only "sees" the sites linked here.
    
    > _Note: This "available vs. enabled" pattern is common on Debian/Ubuntu but may not exist on RHEL/CentOS._
    
- **`snippets/`**: Used to store small, reusable configuration chunks (like SSL settings or common security headers) that you can include in multiple site configurations.
    
- **`mime.types`**: A list of file extensions and their associated content types (e.g., `.html` is `text/html`).
    

---

### 2. The Content Directory: `/var/www/`

This is where your actual website files (HTML, CSS, JS, Images) are typically stored.

- **`/var/www/html/`**: The default root directory for the "Welcome to NGINX" page.
    
- **Custom Folders**: For multiple sites, you would typically create folders like `/var/www/example.com/public_html`.7
    

---

### 3. The Log Directory: `/var/log/nginx/`

When something goes wrong or you need to see who is visiting, you check here.

- **`access.log`**: Records every request made to the server.
    
- **`error.log`**: Records server errors, configuration issues, or connection failures.

### Visual Representation of the Structure

Plaintext

```
/etc/nginx/
├── nginx.conf                 # Global settings
├── mime.types                 # File type mappings
├── conf.d/                    # Global config snippets
│   └── ssl.conf
├── snippets/                  # Reusable config blocks
│   └── fastcgi-php.conf
├── sites-available/           # All site configurations
│   ├── example.com.conf
│   └── shop.io.conf
└── sites-enabled/             # Active site configurations
    ├── example.com.conf -> ../sites-available/example.com.conf
    └── shop.io.conf -> ../sites-available/shop.io.conf

/var/www/                      # Web content
├── example.com/
│   └── index.html
└── shop.io/
    └── index.html

/var/log/nginx/                # Logs
├── access.log
└── error.log
```

### Full Configuration Example (Standard Site Setup)

If you were setting up a new site, you would create a file in `/etc/nginx/sites-available/mysite.com`.

Nginx

```
# /etc/nginx/sites-available/mysite.com

server {
    listen 80;
    listen [::]:80;

    # The domain name this config responds to
    server_name mysite.com www.mysite.com;

    # Where the website files live
    root /var/www/mysite.com/html;
    index index.html index.htm;

    # Log locations for this specific site
    access_log /var/log/nginx/mysite_access.log;
    error_log /var/log/nginx/mysite_error.log;

    location / {
        # Try to serve file, then directory, then fall back to 404
        try_files $uri $uri/ =404;
    }

    # Custom 404 page
    error_page 404 /404.html;
    location = /404.html {
        internal;
    }
}
```
