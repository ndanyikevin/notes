NGINX (pronounced "engine-ex") is an open-source software that acts as a **web server**, **reverse proxy**, **load balancer**, and **HTTP cache**.1

Originally created by Igor Sysoev in 2004 to solve the "C10k problem" (the challenge of handling 10,000 concurrent connections), it has become one of the most popular tools for powering high-traffic websites because of its speed and efficiency.2

---

## Core Functions

### 1. Web Server

Like Apache, NGINX can serve static content (HTML, CSS, images) directly to users.3 It is highly optimized for this and consumes very little memory compared to older server technologies.4

### 2. Reverse Proxy

This is one of NGINX's most common uses. It sits in front of your application servers (like Node.js, Python, or Java) and directs client requests to them.5 This adds a layer of security and abstraction.6

### 3. Load Balancer

If you have multiple servers running your app, NGINX can distribute incoming traffic across them.7 This ensures no single server gets overwhelmed and improves the availability of your site.8

### 4. API Gateway

NGINX can handle authentication, rate limiting, and request routing for microservices, making it a powerful entry point for modern APIs.9

---

## Why Use NGINX?

- **Event-Driven Architecture:** Unlike servers that create a new "thread" or process for every connection, NGINX uses an asynchronous, non-blocking approach.10 This allows it to handle thousands of connections simultaneously with very low overhead.
    
- **Performance:** It is significantly faster at serving static files than most other web servers.
    
- **Versatility:** It can handle HTTP, HTTPS, gRPC, and even TCP/UDP traffic.11
    
- **Security:** It can hide the identity of your backend servers and provide SSL/TLS termination (handling the encryption so your app doesn't have to).12

## Basic Configuration Example

As per your preference for full components/files, here is a standard example of an NGINX configuration file (`nginx.conf`) that sets up a reverse proxy with SSL.

Nginx

```
# Main NGINX configuration file
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile        on;

    # Define a group of backend servers for load balancing
    upstream my_backend_app {
        server 127.0.0.1:3000; # Local app instance 1
        server 127.0.0.1:3001; # Local app instance 2
    }

    server {
        listen       80;
        server_name  example.com;

        # Redirect all HTTP traffic to HTTPS
        return 301 https://$host$request_uri;
    }

    server {
        listen       443 ssl;
        server_name  example.com;

        # SSL Certificate paths
        ssl_certificate      /etc/nginx/ssl/example.com.crt;
        ssl_certificate_key  /etc/nginx/ssl/example.com.key;

        # Main location block - Proxying to the upstream group
        location / {
            proxy_pass http://my_backend_app;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }

        # Serving static files directly
        location /static/ {
            root /var/www/html;
            expires 30d;
        }
    }
}
```
