The **`nginx.conf` file** is the **main configuration file** for NGINX.  
It’s hierarchical and block-based, and **order + nesting really matters**.

I’ll explain it **top → down**, then show a **full annotated example**.

---

## 1️⃣ High-level structure

```nginx
# Global context
events {
}

http {
    server {
        location {
        }
    }
}
```

Think of it as **layers**:

```
Global
 └── events
 └── http
      └── server
           └── location
```

---

## 2️⃣ Global context

📍 **Outside any block**

Used for:

- worker processes
    
- logging
    
- user permissions
    

Example:

```nginx
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid;
```

### Important directives

- `worker_processes` → number of worker processes
    
- `error_log` → global error log
    
- `pid` → process ID file
    

---

## 3️⃣ `events` block

📍 Controls **how NGINX handles connections**

```nginx
events {
    worker_connections 1024;
}
```

### Key directive

- `worker_connections`  
    Max connections **per worker**
    

Total max connections ≈  
`worker_processes × worker_connections`

---

## 4️⃣ `http` block (most important)

📍 Everything related to **HTTP traffic**

```nginx
http {
    include mime.types;
    default_type application/octet-stream;

    sendfile on;
    keepalive_timeout 65;

    server {
    }
}
```

### Common things here

- MIME types
    
- logging formats
    
- gzip
    
- proxy settings
    
- caching
    
- virtual hosts (`server` blocks)
    

---

## 5️⃣ `server` block (virtual host)

📍 Represents **one website or domain**

```nginx
server {
    listen 80;
    server_name example.com;
}
```

### Key directives

- `listen` → port (80, 443)
    
- `server_name` → domain name
    
- `root` → document root
    
- `index` → default file
    

You can have **many server blocks**.

---

## 6️⃣ `location` block (routing rules)

📍 Handles **specific URLs**

```nginx
location / {
    try_files $uri $uri/ =404;
}
```

### Common patterns

- `/` → everything
    
- `/api/` → API routes
    
- `~ \.php$` → regex match
    

### Examples

```nginx
location /api/ {
    proxy_pass http://backend;
}

location /static/ {
    root /var/www;
}
```

---

## 7️⃣ Named & special blocks

### `upstream` (load balancing)

```nginx
upstream backend {
    server localhost:3000;
    server localhost:3001;
}
```

Used inside `http`, referenced by `proxy_pass`.

---

### `map` (variable logic)

```nginx
map $request_method $is_post {
    POST 1;
    default 0;
}
```

---

## 8️⃣ Includes (very common in real setups)

```nginx
http {
    include /etc/nginx/conf.d/*.conf;
}
```

This allows:

- clean structure
    
- multiple files
    
- per-service configs
    

---

## 9️⃣ Full example (reverse proxy)

```nginx
user nginx;
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include mime.types;
    default_type application/octet-stream;

    upstream api_backend {
        server api:3000;
        server api2:3000;
    }

    server {
        listen 80;
        server_name localhost;

        location /api/ {
            proxy_pass http://api_backend;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }

        location / {
            root /usr/share/nginx/html;
            index index.html;
        }
    }
}
```

---

## 10️⃣ Context rules (VERY IMPORTANT)

Not every directive works everywhere.

|Directive|Valid context|
|---|---|
|`worker_processes`|global|
|`worker_connections`|events|
|`gzip`|http, server, location|
|`proxy_pass`|location|
|`server_name`|server|

Putting a directive in the wrong context = ❌ error.

---

## Mental model to remember

- **Global** → how NGINX runs
    
- **events** → connections
    
- **http** → web behavior
    
- **server** → domain / port
    
- **location** → URL routing
