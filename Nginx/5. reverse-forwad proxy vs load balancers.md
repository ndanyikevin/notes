
## 1️⃣ Reverse Proxy

### What it is

A **reverse proxy** sits **in front of servers** and receives requests **from clients**.

```
Client → Reverse Proxy → Backend server(s)
```

### Main job

- Forward requests to backend services
    
- Hide backend servers
    
- Apply cross-cutting concerns
    

### Common features

- SSL termination (HTTPS)
    
- Routing (`/api → api-server`)
    
- Caching
    
- Security headers
    
- Authentication
    

### Example tools

- NGINX
    
- Traefik
    
- Envoy
    
- Kubernetes Ingress
    

---

## 2️⃣ Forward Proxy

### What it is

A **forward proxy** sits **in front of clients** and makes requests **on their behalf**.

```
Client → Forward Proxy → Internet servers
```

### Main job

- Control outbound traffic
    
- Hide client identity
    

### Common features

- Website blocking
    
- Logging user activity
    
- Caching
    
- IP masking
    

### Example tools

- Squid
    
- TinyProxy
    
- Corporate proxies
    
- VPNs (conceptually similar)
    

---

## 3️⃣ Load Balancer

### What it is

A **load balancer** distributes traffic **across multiple backend servers** to avoid overload.

```
Client → Load Balancer → Server A / Server B / Server C
```

### Main job

- Spread traffic evenly
    
- Increase availability
    
- Handle server failures
    

### Common features

- Health checks
    
- Failover
    
- Sticky sessions
    
- Scaling support
    

### Example tools

- NGINX
    
- HAProxy
    
- AWS ALB / NLB
    
- Cloudflare
    

---

## Key difference at a glance

|Feature|Forward Proxy|Reverse Proxy|Load Balancer|
|---|---|---|---|
|Sits in front of|Clients|Servers|Servers|
|Who configures it|Client|Server owner|Server owner|
|Hides|Client|Backend|Backend|
|Primary goal|Outbound control|Request handling|Traffic distribution|
|Can route paths|❌|✅|Sometimes|
|Can do SSL|❌ / Limited|✅|✅|

---

## Important insight (this is the tricky part)

> **A load balancer is often a reverse proxy — but not every reverse proxy is a load balancer.**

### Example:

- NGINX acting as:
    
    - reverse proxy ✅
        
    - load balancer ✅
        
    - SSL terminator ✅
        

But you can also have:

- Reverse proxy → single backend (no load balancing)
    
- Load balancer → pure L4 (no HTTP awareness)
    

---

## Layer difference (very important)

|Layer|Forward Proxy|Reverse Proxy|Load Balancer|
|---|---|---|---|
|L4 (TCP/UDP)|❌|❌|✅|
|L7 (HTTP)|✅|✅|✅|

Examples:

- **L4 Load Balancer**: AWS NLB (no URLs, just ports)
    
- **L7 Reverse Proxy / LB**: NGINX, AWS ALB
    

---

## Real-world architecture example

```
Users
  ↓
NGINX (Reverse Proxy + Load Balancer)
  ↓
  ├─ API instance 1
  ├─ API instance 2
  └─ API instance 3
```

Here:

- NGINX = reverse proxy
    
- NGINX = load balancer
    
- Backend servers are hidden
    

---

## Simple rule to remember

- **Forward proxy** → protects & controls **clients**
    
- **Reverse proxy** → protects & manages **servers**
    
- **Load balancer** → spreads traffic **between servers**
