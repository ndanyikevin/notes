A **reverse proxy in NGINX** is when NGINX sits **in front of one or more backend servers** and **forwards client requests to them**, then sends the response back to the client.

From the client’s point of view, it looks like it’s talking **only to NGINX**, not to your backend app.

---

## Simple idea (mental model)

```
Browser → NGINX → Backend app (API, website, service)
```

NGINX:

- receives the request
    
- decides **where to send it**
    
- forwards it
    
- returns the response
    

---

## Why use NGINX as a reverse proxy?

### 1. Hide backend servers

Clients never see:

- internal IPs
    
- ports (e.g. `localhost:3000`, `:8080`)
    

Only NGINX is public.

---

### 2. Route traffic

NGINX can send requests to different services:

```
/api   → backend API
/      → frontend app
```

---

### 3. Load balancing

One NGINX → many backend servers

```
NGINX
 ├── app1
 ├── app2
 └── app3
```

NGINX distributes traffic automatically.

---

### 4. SSL termination

NGINX handles HTTPS:

- decrypts SSL
    
- forwards plain HTTP to backend
    

Backend apps don’t need SSL logic.

---

### 5. Performance & security

- caching
    
- rate limiting
    
- request filtering
    
- protection against direct attacks on backend
    

---

## Basic reverse proxy example

### Backend app (running on port 3000)

Example: Express, Hono, Bun, etc.

```
http://localhost:3000
```

---

### NGINX config

```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://localhost:3000;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### What happens

1. User visits `http://example.com`
    
2. NGINX receives request
    
3. NGINX forwards it to `localhost:3000`
    
4. Backend responds
    
5. NGINX sends response to user
    

---

## Multiple services example

```nginx
server {
    listen 80;

    location /api/ {
        proxy_pass http://localhost:4000;
    }

    location / {
        proxy_pass http://localhost:3000;
    }
}
```

```
/api/users  → API server (4000)
/            → Frontend (3000)
```

---

## Reverse proxy vs Forward proxy (important difference)

|Forward Proxy|Reverse Proxy|
|---|---|
|Used by clients|Used by servers|
|Hides the client|Hides the backend|
|Example: VPN|Example: NGINX|

---

## Real-world analogy

Think of NGINX as a **receptionist**:

- Clients talk to the receptionist
    
- The receptionist knows which office (backend) to send them to
    
- Clients never walk into the offices directly
