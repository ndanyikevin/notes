Commands for NGINX fall into two categories: **Service Management** (system-level commands to start/stop) and **Binary Commands** (direct interaction with the NGINX software to test or signal it).

---

### 1. Service Management Commands

On modern Linux systems (Ubuntu, Debian, CentOS 7+), NGINX is managed as a service using `systemctl`. These are the commands you will use most frequently.

| **Task**    | **Command**                    | **Description**                                                       |
| ----------- | ------------------------------ | --------------------------------------------------------------------- |
| **Start**   | `sudo systemctl start nginx`   | Turns the server on.                                                  |
| **Stop**    | `sudo systemctl stop nginx`    | Turns the server off (abruptly).                                      |
| **Restart** | `sudo systemctl restart nginx` | Stops and then starts the server.                                     |
| **Reload**  | `sudo systemctl reload nginx`  | **Recommended:** Applies config changes without dropping connections. |
| **Status**  | `sudo systemctl status nginx`  | Checks if NGINX is running and shows recent error logs.               |
| **Enable**  | `sudo systemctl enable nginx`  | Ensures NGINX starts automatically when the server reboots.           |

---

### 2. NGINX Binary Commands

These commands interact directly with the `nginx` executable.1 They are vital for troubleshooting before you commit to a restart.

- Test Configuration:
    
    sudo nginx -t
    
    Crucial: Always run this after editing a config file.2 It checks for syntax errors (like missing semicolons) and tells you exactly which line is broken.
    
- Check Version:
    
    nginx -v (Version only) or nginx -V (Version + compiler arguments and installed modules).3
    
- Direct Signals (-s flag):
    
    If you aren't using systemctl, you can send signals directly:4
    
    - `sudo nginx -s reload`: Graceful reload.
        
    - `sudo nginx -s quit`: Graceful shutdown (waits for active connections to finish).5
        
    - `sudo nginx -s stop`: Immediate shutdown.
        

---

### 3. Log Inspection Commands

Since NGINX is often a "silent" service, you use standard Linux commands to read its output.

- Follow Error Logs in Real-time:
    
    sudo tail -f /var/log/nginx/error.log
    
- View Recent Access History:
    
    sudo tail -n 50 /var/log/nginx/access.log
    

---

### Practical Workflow Example

If you have just finished editing a site configuration file, your workflow should look like this:

Bash

```
# 1. Check for syntax errors (Don't skip this!)
sudo nginx -t

# 2. If 'syntax is ok', apply the changes gracefully
sudo systemctl reload nginx

# 3. Verify the service is still active
sudo systemctl status nginx
```
