
## 🌐 **What Is a Webhook?**

A **webhook** is a way for one system (app A) to **automatically send data to another system (app B)** **when an event happens** — without app B needing to keep asking for updates.

> In simple terms:  
> **A webhook = automatic notification + data delivery between two systems.**

---

## 💬 **Simplified Example**

Let’s say your **school management app** is connected to a **payment system** like Stripe.

- When a parent pays school fees, Stripe sends a **webhook** (HTTP POST request) to your app’s URL, telling it:  
    “✅ Payment received for Student #101, KES 20,000.”
    

So your system can instantly update the student’s fee status **without checking Stripe repeatedly**.

---

## ⚙️ **How a Webhook Works**

1. **App A (Sender)** — has events that can trigger webhooks (e.g., new payment, new student, updated grade).
    
2. **App B (Receiver)** — provides a special **URL endpoint** that listens for incoming webhooks.
    
3. When an event happens, **App A sends an HTTP POST** with the event data to that URL.
    
4. **App B processes** the data automatically (e.g., updates its database, sends a message, triggers a workflow).
    

---

### 📬 **In Technical Terms**

A webhook is just:

- An **HTTP POST request**
    
- Sent by one service to another
    
- Containing **JSON data** about an event
    

---

## 🧠 **Example in JSON**

When a parent pays through an external payment gateway, your app might receive:

```json
{
  "event": "payment_successful",
  "student_id": "101",
  "amount": 20000,
  "method": "M-Pesa",
  "timestamp": "2025-10-10T09:00:00Z"
}
```

Your app’s endpoint:

```
POST https://schoolapp.com/api/webhooks/payments
```

You can then:

- Update `fees_balance` in the database
    
- Notify the bursar
    
- Send SMS confirmation to the parent
    

All automatically — no manual action needed.

## 🧮 **Webhook vs API Polling**

|Feature|**Webhook**|**Polling**|
|---|---|---|
|**Who starts communication?**|Sender (automatic)|Receiver (asks repeatedly)|
|**When sent?**|When an event happens|At fixed time intervals|
|**Network load**|Low (only on change)|High (constant checks)|
|**Delay**|Instant|Delayed (depends on polling rate)|

**Webhook = Push model (event-driven)**  
**Polling = Pull model (request-based)**

---

## 🧩 **Analogy**

Imagine:

- **Polling**: You keep asking the teacher every minute — “Any new marks yet?”
    
- **Webhook**: The teacher tells you immediately when marks are ready.

## 🛠️ **Code Example (Express.js Webhook Receiver)**

```js
import express from "express";
const app = express();

app.use(express.json());

// Webhook endpoint
app.post("/webhook/payment", (req, res) => {
  const event = req.body;

  if (event.type === "payment_successful") {
    console.log(`Student ${event.student_id} paid ${event.amount}`);
    // Update DB, send notification, etc.
  }

  res.status(200).send("Webhook received!");
});

app.listen(3000, () => console.log("Webhook listener running on port 3000"));
```

## 🔒 **Webhook Security Tips**

|Practice|Why|
|---|---|
|✅ **Use HTTPS**|Encrypt data in transit|
|🔑 **Verify signatures**|Make sure data came from a trusted source|
|🔄 **Handle retries**|Webhook providers may resend if you don’t respond fast|
|🕒 **Acknowledge quickly**|Respond with `200 OK` quickly, process in background|

## 🧠 **In Short**

> A **webhook** is a way for one system to **push data automatically** to another system when something happens —  
> enabling **real-time, event-driven communication** between apps.
